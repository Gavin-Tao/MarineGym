# ⚠️ 作废数据 —— 不要用于论文

这批评测（32 个文件，含 `strong`/`fast` 档）建立在 **2026-08-26 阵风 reset 计时 bug 修复之前**
训练出来的策略上（`checkpoint_4104192.pt`，commit 4ddf49c 之前）。

## 为什么作废

`IsaacEnv` 的 reset 顺序是先 `_reset_idx(env_ids)` 再 `progress_buf[env_ids] = 0`
（`isaac_env.py:275/277`）。阵风在 `_reset_idx` 里发射时读到的是**上一 episode 的末值**
（≈599），于是起风时刻与下次重发都被排到新 episode 永远追不上的未来 ——
**第一个 episode 之后再也不发阵风**。

后果：训练跑 410 万步，绝大多数 episode 实际是**无扰动**的，所以那条策略从未见过阵风。
拿它去评测有阵风的场景，只比随机策略好 40%。这批数据测的是"一条没见过扰动的策略在
扰动下的表现"，不是方法的效果。

## 保留它做什么

1. 作为该 bug 影响范围的证据；
2. 与修复后的同口径结果对照，可以量化"策略是否见过扰动"带来的差别 ——
   如果需要，这本身可以作为论文里"训练分布必须覆盖部署扰动"的一个附带论据。

- `../regress/`（V0–V3 环境验证）：走廊/阵风默认关闭，不受影响，修复后重跑仍逐位通过
- `../k4/`（K4 观测器判决）：300 步单次 reset 采集，全程在第一个 episode 内，阵风正常
- `../calib/`（场景标定扫描）：评测长度，大多是第一个 episode，阵风正常
